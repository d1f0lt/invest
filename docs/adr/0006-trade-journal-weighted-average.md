# ADR-0006: Журнал операций и метод средневзвешенной стоимости

## Контекст

Исходная формулировка задачи — «хранить список акций». Но приложению нужна
полная прибыль, в том числе по полностью проданным бумагам, а также
дивиденды, купоны, налоги и комиссии. При хранении только текущего
количества эта информация теряется безвозвратно.

## Решение

- `portfolio` хранит **неизменяемые журналы**: `trades` (сделки) и
  `cash_operations` (денежные операции). Позиции, P&L и стоимость по дням
  вычисляются при каждом запросе.
- Метод расчёта — **средневзвешенная стоимость** (moving average cost),
  как у большинства брокерских приложений: покупка пересчитывает среднюю
  цену с учётом комиссии, продажа фиксирует прибыль относительно неё.
- Расчёт — чистые функции в `internal/pnl` с юнит-тестами на числовых
  примерах, без обращения к БД.
- Полный результат:
  `total_pnl = realized + unrealized + дивиденды + купоны + НКД + налоги + комиссии вне сделок + прочее`.
  Пополнения и выводы в прибыль не входят. Проверка:
  `рыночная стоимость + cash_balance − net_deposits = total_pnl`

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| Таблица «тикер → количество» | просто | теряется история и реализованная прибыль |
| FIFO / LIFO по лотам | соответствует налоговому учёту | сложнее, для личного портфеля не требуется |
| **Журнал + средневзвешенная цена** | любая метрика восстановима из журнала | расчёт на каждом запросе |

## Последствия

**Положительные:** можно пересчитать всё задним числом при изменении
формулы; повторные импорты не искажают итоги.

**Отрицательные и риски:** нет FIFO/LIFO, шортов и конвертации валют;
нет API исправления или удаления ошибочной сделки; при большом журнале
расчёт может замедлиться (пагинации и кэша нет).
