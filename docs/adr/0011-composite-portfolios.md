# ADR-0011: Составные портфели: расчёт по участникам и слияние

## Контекст

У инвестора бывает несколько счетов (у разных брокеров), и он хочет видеть
их вместе. Если просто объединить журналы, средняя цена посчитается по
«общему котлу»: продажа на одном счёте «съест» бумаги другого, а
реализованная прибыль не совпадёт с суммой по счетам.

## Решение

- Составной портфель — обычная строка `portfolios` плюс состав в
  `portfolio_members` (`position` — порядок). Своих операций у него нет.
- Создаётся через `CreatePortfolio` с `member_ids` (не меньше двух обычных
  портфелей пользователя). Вложенность запрещена: без неё не бывает циклов
  и двойного счёта. Состав после создания не меняется.
- Чтение журналов возвращает строки всех участников.
- `GetPnL` и `GetHoldings` считаются **по каждому участнику отдельно**
  (`pnl.Compute`) и складываются (`pnl.Merge`); средняя цена —
  взвешенная по количеству. История стоимости складывается по точкам.
- Запись в составной портфель (сделки, импорт) — `FAILED_PRECONDITION`.

## Последствия

**Положительные:** итоги составного портфеля точно равны сумме итогов
счетов.

**Отрицательные и риски:** состав нельзя изменить; нет API удаления
портфелей.
