# ADR-0001: Микросервисы на Go с общей базой PostgreSQL

## Текущее состояние

- Один кластер PostgreSQL, одна база `invest` для всех сервисов.
- Каждая таблица принадлежит одному сервису: он в неё пишет и хранит её
  миграции. Читать чужие таблицы допустимо.
- **Связи между таблицами:**
  - FK на `securities(secid, board)` есть: бесплатная защита от опечаток
    в тикере и JOIN с `latest_prices` для текущей стоимости;
  - FK на `users.id` нет: `user_id` берётся из контекста аутентификации,
    и сервисы логически независимы, хотя физически делят один Postgres.

## Аргументы

| За общую БД | Против |
|---|---|
| бесплатная ссылочная целостность через FK | связность миграций: `run-migrations.sh` обязан накатывать `price_updater` раньше `portfolio` |
| транзакционно согласованные JOIN: P&L читает `trades` + `latest_prices` одним запросом, без вызова другого сервиса | общий «радиус поражения» при сбое или ошибочной миграции |
| операционная простота одного Postgres при соло-разработке | неполная независимость выкатки сервисов |

## Последствия

**Положительные:** простая инфраструктура; FK на справочник бумаг; быстрый
расчёт стоимости портфеля.

**Отрицательные и риски:** схема `securities` и `latest_prices` — неявный
контракт между сервисами (их читают `securities_reader`, `portfolio`,
`notifier`); при разделении баз FK на `securities` придётся убрать
и проверять бумагу через gRPC.
