# ADR-0010: Развёртывание: один сервер, Docker Compose, выкатка по тегу

## Контекст

Нужен воспроизводимый способ выкатывать backend и Android-приложение без
ручных действий на сервере, с возможностью отката.

## Решение

- Production — тот же `docker-compose.yml`, что и локально. Отличия задаются
  переменными: `IMAGE_TAG`, `GATEWAY_BIND=127.0.0.1`, `COMPOSE_PROFILES=https`,
  `API_DOMAIN`.
- Выкатка — по git-тегу `v*`: CI → образы в GHCR (`ghcr.io/d1f0lt/invest/<svc>:<tag>`)
  → копирование compose-файлов, скриптов и миграций по SSH → `deploy.sh`
  (pull → миграции → up → ожидание healthy gateway → чистка образов) →
  проверка `/healthz`.
- Откат — ручной запуск workflow с уже собранным тегом, без пересборки.
- HTTPS — Caddy с автоматическим сертификатом Let's Encrypt на порту
  **8443**; домен DuckDNS.
- Тот же тег собирает подписанный APK и публикует его в GitHub Releases.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| Kubernetes | масштабирование, самовосстановление | избыточен для одного сервера |
| Ручная выкатка | ничего настраивать не надо | невоспроизводимо, ошибки |
| **Compose + Actions** | один файл описывает всё окружение; простой откат | один сервер — единая точка отказа |

## Последствия

**Положительные:** выкатка и откат одной командой; одинаковая конфигурация
локально и на сервере.

**Отрицательные и риски:** нет staging; нет zero-downtime (контейнеры
пересоздаются); единая точка отказа;
