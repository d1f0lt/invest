# ADR-0009: SeaweedFS вместо MinIO

## Контекст

Для файлов отчётов использовался MinIO. MinIO перестал публиковать
community-образы (`minio/minio`, `minio/mc` на Docker Hub), а закреплённые
ссылки на quay.io перестали резолвиться, так что стек больше не собирался.

## Решение

- S3-хранилище — SeaweedFS (`chrislusf/seaweedfs:4.06`) в одном контейнере
  (master + volume + filer + S3 gateway), сервис `s3`, порт 9000.
- Ключи доступа берутся из `.env` (`S3_ACCESS_KEY`, `S3_SECRET_KEY`) и при
  старте записываются в конфигурацию S3 identities.
- Бакет `reports` создаёт одноразовый сервис `s3-init` через `weed shell`.
- `gateway` и `parser` используют S3-клиент `minio-go`. Подключение задают
  `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` и `S3_USE_SSL`.

## Последствия

**Положительные:** стек снова собирается из публичных образов; в коде
сервисов ничего не завязано на конкретный S3-сервер.

**Отрицательные и риски:** у SeaweedFS нет веб-консоли управления объектами.
